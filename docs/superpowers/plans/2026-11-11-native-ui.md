# Нативний UI та композиція застосунків (Native UI & Composition) — Implementation Plan

> **Для агентних виконавців:** ОБОВ'ЯЗКОВО: використати `superpowers:subagent-driven-development` (рекомендовано) або `superpowers:executing-plans` для виконання цього плану по завданнях. Кроки використовують checkbox (`- [ ]`) для відстеження.

**Воркспейс:** гілка `feature/native-ui` від `main`, **після** мерджу `feature/client-auth-session-presentation` і `feature/native-platform`. Файли, які ця хвиля володіє: `androidApp/**`, `iosApp/**`, `shared/umbrella/src/iosMain/**`, `shared/umbrella/build.gradle.kts` (за потреби). `shared/data/**`, `shared/presentation/**`, `shared/application/**`, `shared/domain/**`, `server/**` — **не** редагуються.

**Мета:** робочі екрани на SwiftUI та Compose поверх наявних MVI-сторів: розблокування/вхід, список vault, деталі, редагування; композиція Koin у кожному застосунку; автоблокування за lifecycle, захист від скриншотів/перемикача задач, 30-секундний буфер і базова accessibility.

**Архітектура:** UI — тонкий: читає `state`, шле `intent`, реагує на `effects`; жодної бізнес-логіки, ключів чи `AppError`-мапінгу в Swift/Compose. Композиційний корінь — у застосунку: Android `Application` + `MainActivity`, iOS — Kotlin-фасад `LockrunaIos`, який Swift викликає, щоб не тягнути Koin у Swift. Секрет показується одноразово з `Effect` і не зберігається в UI-стані.

**Технології:** Compose BOM / Material3 (уже в `androidApp`), SwiftUI + SKIE 0.10.15, Kotlin 2.4.20, Koin 4.2.2. Нових залежностей немає.

**Специфікація:** `docs/requirements.md` (US-02, US-06, US-07, US-08), `docs/adr/002-clean-architecture-mvi.md`, `docs/adr/005-client-shared.md` §9, `docs/threat-model.md`.

## Global Constraints

- Стори й сигнатури — з планів `2026-11-11-client-auth-session-presentation.md` (`LoginStore`, `UnlockStore`, `SessionStore`) і наявних `VaultListStore`, `ItemDetailStore`, `ItemEditStore`. Змінювати стор — заборонено.
- Секрет ніколи не потрапляє в UI-стан: тільки локальна змінна на час показу, очищається при `Hide`/закритті екрана/фоні.
- Пароль — `TextField` з `SecureField`/`PasswordVisualTransformation`, не зберігається в `remember`/`@State` після Submit.
- Автоблокування: у фоні фіксуємо `monotonic`-час, на resume шлемо `SessionIntent.Resumed(ts)`.
- Приватність: Android `FLAG_SECURE` на вікні; iOS — блюр-оверлей при `scenePhase != .active` і банер після скриншота (`UIScreen.capturedDidChangeNotification`).
- Accessibility: таргети ≥ 44 pt, `contentDescription` для іконок, Dynamic Type, контраст Material-теми.
- Код/коментарі/коміти англійською; docs/ українською.
- JDK 25: `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`.
- Не в обсязі: Register/Recovery/Devices/Settings-екрани, тригери sync (кнопка ручного sync — можна), зміна майстер-пароля, CARD/NOTE-поля, локалізація (UI англійською).

## Review Focus

- Старт застосунку при замкненій сесії показує екран розблокування, не порожній vault і не флеш списку; тест у Task 1.
- Поворот екрана/реконфігурація не втрачає введений email і не дублює Submit; Task 2.
- Скриншот і перехід у фон показують заглушку, а не вміст запису; Task 3/6.
- Reveal секрету закриває його при відході у фон і не лишає в стані; Task 2/5.
- Один і той самий екран відкривається з різних місць без другого інстансу стора (factory на екран); Task 1/4.
