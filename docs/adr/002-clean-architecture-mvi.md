# ADR-002: Clean Architecture + DDD-lite, MVI у presentation

- **Статус:** прийнято
- **Дата:** 2026-11-07
- **Пов'язані:** ADR-001, ADR-005

## Контекст

Потрібна архітектура, що відповідає SOLID/GRASP/DRY, тестується без емуляторів і дозволяє один раз написати логіку екранів для iOS і Android.

## Рішення

1. **Шари й залежності.** Залежності спрямовані всередину: `data → application → domain`, `presentation → application`. `domain` не має залежностей від фреймворків. Реалізації портів (SQLDelight, Ktor, крипто, платформні сервіси) живуть у `data` або в нативних застосунках.

2. **DDD-lite.** Bounded contexts:

   | Контекст | Відповідальність |
   |---|---|
   | Identity | реєстрація, вхід, KDF, майстер-пароль, пристрої, відновлення |
   | Vault | записи й папки, шифрування, автоблокування |
   | Sync | дельти, версії, конфлікти |
   | Audit | події безпеки (лише сервер) |

   Агрегати, value objects, порти (`<X>Repository`, `<X>Api`) і use cases. Event Sourcing і CQRS не використовуються.

3. **Дві моделі запису.** На клієнті `VaultItem` розшифрований і існує в пам'яті на час розблокування. У контексті Sync і на сервері існує `EncryptedItem` (ciphertext, nonce, version). Це різні моделі різних контекстів.

4. **MVI у `shared/presentation`.** `State` (data class), `Intent` (sealed interface), `Effect` (одноразові події). Store викликає лише use cases, а не репозиторії. `State` містить `ItemUi` без `secret`, агрегати в `State` не потрапляють. Слово «Store» зарезервоване за MVI-екранами.

5. **Інваріанти живуть в агрегатах**, а не в use cases чи Store.

6. **Presentation залежить від application, але не навпаки.** Заміна підходу до presentation не торкається domain і application.

## Наслідки

- (+) Логіка екранів один раз для обох платформ, `reduce` чиста функція, тести в `commonTest`.
- (+) `locked` єдине джерело правди; автоблокування шле `Lock`.
- (+) Секрети не потрапляють у `State`, а отже в логи та snapshot-тести.
- (−) Більше шарів і мапінгу (`VaultItem → ItemUi`).
- (−) Для SwiftUI потрібен міст до Flow (SKIE).

## Альтернативи

- **TCA:** працює лише на iOS, логіка екранів дублювалась би на Android.
- **Нативні ViewModel ×2:** дублювання логіки й тестів.
- **MVIKotlin:** потужніший, але важчий, ніж потрібно для MVP.
